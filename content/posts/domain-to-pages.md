프로필 사이트를 하나 만들어보고 싶었습니다. 링크 몇 개 있는 간단한 페이지인데,
`github.io` 주소 말고 제 이름으로 된 주소를 쓰고 싶었습니다.

그러려면 도메인이 필요합니다. 사는 것까지는 알겠는데 **산 다음에 그게 어떻게 제 페이지로
연결되는지**를 몰랐습니다. `A` 레코드니 `CNAME` 이니 하는 말은 봤는데 뭘 골라야 하는지도
몰랐고요.

알아보면서 몇 가지가 예상과 달랐습니다. 순서대로 적습니다.

## 도메인은 사는 게 아니라 빌리는 것이었습니다

먼저 도메인이 있어야 합니다. 그런데 결제하려고 보니 "산다" 는 말이 정확하지 않았습니다.
**연 단위 사용권**이고, 갱신하지 않으면 유예기간 뒤에 다른 사람이 등록할 수 있습니다.
자동 갱신을 켜두는 것이 첫 번째 할 일이었습니다.

그리고 등록 후 **60일간은 다른 곳으로 옮길 수 없습니다.** ICANN 규칙이라 어디서 사든
같습니다.[^transfer] 파는 곳이 마음에 안 들어도 두 달은 그대로 씁니다.

두 달이나 묶인다니 어디서 살지를 좀 보게 됐습니다. 가격표를 보다가 두 가지를 알았습니다.

**첫해 가격은 기준이 아닙니다.** 첫해 $2 에 팔고 2년차에 $30 을 받는 곳이 흔합니다.
계속 쓰는 물건이라 실제로 내는 값은 갱신가입니다.

| 레지스트라 | 등록(1년) | 갱신(연) |
|---|---|---|
| **Cloudflare Registrar** | $16.56 | $16.56 |
| Dynadot | $9.56 | $17.53 |
| Namecheap | 할인 | 인상 |
| GoDaddy 류 | 매우 쌈 | 매우 비쌈 |

> 2026년 7월에 `.me` 기준으로 본 값입니다. `.me` 는 몬테네그로 국가 도메인인데
> 등록 제한이 없고 영어로 "나" 를 뜻해서 개인 사이트에 관행적으로 쓰입니다.
> 대신 `.com` 보다 갱신비가 비쌉니다.

**그리고 레지스트라는 판매 창구일 뿐입니다.** 어디서 사든 등록되는 원장은 같습니다.
비싼 곳에서 산다고 도메인이 좋아지지 않습니다. 차이는 가격과 **DNS 기능**과 UI 뿐입니다.

Cloudflare 에서 샀습니다. 갱신가가 등록가와 같고, DNS 기능 하나가 필요했는데 그게
다음 절의 이야기입니다.

## apex 에는 CNAME 을 못 겁니다

`elkiss.me` 처럼 앞에 아무것도 안 붙은 이름을 **apex** 라고 합니다.

GitHub Pages 는 `<계정>.github.io` 라는 **이름**으로 서빙합니다.
그러니 내 도메인을 그 이름으로 넘기면 되겠다 싶었습니다. `CNAME` 이 하는 일입니다.

그런데 apex 에는 안 됩니다.

`CNAME` 의 정의가 "이 이름에 대한 것은 전부 저쪽에서 가져와라" 이기 때문입니다.
필드 하나를 가리키는 게 아니라 이름 전체를 대체합니다.
그래서 **`CNAME` 이 있는 이름에는 다른 레코드가 함께 있을 수 없습니다.**[^cname]

그런데 apex 는 `NS` 와 `SOA` 를 반드시 가져야 합니다. 없으면 위임이 성립하지 않습니다.

```
apex 에 CNAME 을 걸면  → 다른 레코드가 있으면 안 된다
그런데 apex 는         → NS, SOA 가 반드시 있어야 한다
                       → 동시에 성립 불가
```

서브도메인은 `NS`·`SOA` 가 필요 없어서 이 제약이 없습니다.

**Cloudflare 는 이 사이를 CNAME flattening 으로 메웁니다.** 설정 화면에서는 apex 에
`CNAME` 을 거는 것처럼 보이지만, 질의가 들어오면 Cloudflare 가 대신 대상을 조회해서
나온 IP 를 `A` 로 응답합니다. 표준을 어기지 않습니다.

같은 기능을 다른 업체는 ALIAS 나 ANAME 이라고 부릅니다.
**표준이 아니라 업체별 기능이라 이름이 제각각이고, 없는 곳도 있습니다.**
앞 절에서 DNS 기능을 봤다고 한 게 이것입니다.

하나 더 있습니다. Cloudflare 에서 레코드를 넣을 때 **프록시(주황 구름)를 끄고
DNS only 로 둬야 합니다.** 켜면 응답 IP 가 Cloudflare 것으로 바뀌어서 GitHub 의
도메인 검사가 통과하지 못합니다. 고른 이유가 된 기능과 켜면 안 되는 스위치가
같은 화면에 있습니다.

## IP 를 적어두면 그날은 됩니다

apex 에 `CNAME` 을 못 건다면 `A` 레코드로 IP 를 직접 적으면 됩니다.
GitHub 이 Pages 용 IP 를 문서에 공개해두고 있으니 그대로 넣으면 그날 사이트가 뜹니다.

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

되기는 하는데, 이 넷은 **고정하겠다는 약속이 아닙니다.**
`A` 로 간다는 것은 이 값을 손으로 적어두고 GitHub 이 바꾸면 따라 고치겠다는 뜻입니다.
안 고치면 그날 사이트가 죽습니다. 배포를 한 적도 설정을 건드린 적도 없는데 어느 날
안 열립니다.

| | `A` | `CNAME` |
|---|---|---|
| 가리키는 것 | IP | **다른 이름** |
| 대상이 바뀌면 | 직접 고쳐야 한다 | 자동으로 따라간다 |

flattening 이 하는 일이 이것입니다. 설정은 `CNAME` 으로 두고 응답만 `A` 로 나가니,
GitHub 이 IP 를 바꿔도 따라갑니다.

> **"DNS 전파" 는 무언가 퍼져나가는 게 아니었습니다.**
> 레코드마다 `TTL` 이 붙고 그동안 리졸버는 캐시된 답을 줍니다.
> 무효화 브로드캐스트 같은 건 없어서, 전파를 기다린다는 것은
> **전 세계 리졸버의 캐시가 각자 만료되기를 기다린다는 뜻입니다.**

## Pages 를 켰더니 저장소가 통째로 올라갔습니다

DNS 가 붙으면 Pages 를 켭니다. 여기서 방식이 둘입니다.

**기본값인 `Deploy from a branch` 는 저장소 루트를 통째로 올립니다.**
`index.html` 만 올라가는 게 아니라 저장소에 있는 것이 다 올라갑니다.

이 블로그가 그 방식이었다면 `blog.elkiss.me/docs/LOG.md` 로 작업 일지가 열렸을 겁니다.
public 저장소라 유출은 아닙니다. 어차피 GitHub 에서 볼 수 있는 파일입니다.
다만 작업 문서가 개인 도메인에서 서비스되고 검색엔진에 색인될 이유는 없습니다.

하나가 더 붙습니다. **`index.html` 이 없으면 Pages 가 Jekyll 을 돌립니다.**
`README.md` 를 기본 테마로 렌더링해서 보여줍니다. Jekyll 을 쓰겠다고 한 적이 없는데
기본 동작이 그렇습니다. 응답 HTML 에 `Jekyll SEO tag` 주석이 남아 있어서 알았습니다.

| | `Deploy from a branch` | 커스텀 Actions |
|---|---|---|
| 올라가는 것 | 저장소 루트 전부 | 워크플로가 고른 것만 |
| `docs/` | 도메인에서 열린다 | 담기지 않는다 |
| `index.html` 이 없으면 | Jekyll 이 `README.md` 를 그린다 | 해당 없음 |
| 설정 | 클릭 두 번 | 워크플로 파일 하나 |

커스텀 Actions 로 옮겼습니다. 워크플로에서 배포할 것만 골라 담으니
`docs/` 와 `README.md` 는 아예 안 실립니다.

### `CNAME` 이 두 군데 나오는데 서로 다른 물건입니다

Pages 에 커스텀 도메인을 저장하면 GitHub 이 **저장소 루트에 `CNAME` 파일을 만듭니다.**
그리고 그 커밋을 자기가 합니다.

```
커밋   f221818
작성자 elkiss87
제목   Create CNAME
```

**제 이름으로 들어와 있습니다.** 웹에서 일어난 일이라 그렇습니다.
만들지 않은 커밋이 제 히스토리에 제 이름으로 남았습니다.
로컬은 이걸 모르니 `ahead 1, behind 1` 로 갈라집니다. `git pull --rebase` 로 풉니다.

이름이 겹쳐서 헷갈렸는데, 둘은 층이 다른 물건이었습니다.

| | `CNAME` 레코드 | `CNAME` 파일 |
|---|---|---|
| 어디에 | DNS | 저장소 루트 |
| 하는 일 | **이 이름을 저 이름으로 넘긴다** | **이 저장소가 받을 도메인은 이것이다** |
| 없으면 | 주소가 GitHub 을 못 찾는다 | GitHub 이 어느 도메인인지 모른다 |

**방향이 반대입니다.** 레코드는 밖에서 안으로 오는 길이고, 파일은 안에서
"나는 이 이름으로 불린다" 고 말하는 쪽입니다. 둘 다 있어야 연결됩니다.

그래서 워크플로에서 골라 담을 때 **`CNAME` 을 빼먹으면 커스텀 도메인이 풀립니다.**

마지막으로 GitHub 이 Let's Encrypt 인증서를 발급하면 **Enforce HTTPS** 를 켭니다.
발급되는 동안은 체크박스가 눌리지 않습니다.

## 블로그는 CNAME 한 줄이었습니다

나중에 이 블로그를 붙일 때는 위의 것이 대부분 필요 없었습니다.

`blog.elkiss.me` 는 서브도메인입니다. apex 가 아니니 `CNAME` 을 그냥 걸 수 있고,
flattening 도 `A` 레코드도 필요 없습니다.
Cloudflare 에 `blog` → `<저장소>.github.io` 한 줄, DNS only. 그게 전부였습니다.

돈도 안 듭니다. 사는 것은 `elkiss.me` 하나뿐이고 그 아래는 무제한입니다.

```
elkiss.me          ← 구매 대상
├─ www.elkiss.me   ← 무료
├─ blog.elkiss.me  ← 무료
└─ 임의.elkiss.me   ← 무료
```

Pages 는 저장소 하나당 커스텀 도메인 하나라서, 블로그는 별도 저장소로 만들고
서브도메인이 그 저장소를 받았습니다.

처음에 헤맨 것 중 꽤 많은 것이 apex 때문이었습니다.
`blog.` 를 앞에 붙이면 `CNAME` 제약도 flattening 도 해당이 없어집니다.

[^transfer]: ICANN 의 레지스트라 간 이전 정책(Inter-Registrar Transfer Policy)입니다. 등록·이전 직후 60일간 다른 레지스트라로의 이전이 제한됩니다.

[^cname]: [RFC 1034](https://www.rfc-editor.org/rfc/rfc1034) 와 [RFC 2181](https://www.rfc-editor.org/rfc/rfc2181) 이 정하는 제약입니다. `CNAME` 이 있는 이름에 다른 타입의 레코드가 함께 존재할 수 없습니다.
